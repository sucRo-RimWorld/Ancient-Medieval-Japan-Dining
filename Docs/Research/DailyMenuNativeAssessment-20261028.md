## 要件に対する実際の対応

| 要件 | Daily Menuそのまま | AMJ側で必要な部分 |
|---|---|---|
| 食事時刻が揃わなくても各自が食べる | 通常の空腹を契機に餐台へ行く仕組みあり | 同期時刻システムは不要 |
| 完成料理を備蓄し、空腹時に組み合わせる | 異なる料理の餐台から最大3種を選択・取餐 | 主食・汁・菜の分類と選択方針 |
| 空腹に応じた分量と在庫減算 | 小分け栄養、端数残量、原料・腐敗状態の引き継ぎあり | 主食と副食の配分は別設計。原実装の等分を承認したわけではない |
| 一つの膳アイテムを持ち、一回で食べる | **なし**。原実装は3個の食品を持ち、3個のIngestを連続実行 | 小分け食品を保持する一膳アイテムと一回のIngest。実ゲーム試作で成立 |
| 副食不足で通常食を止めない | 1種だけでも取餐Jobを提示することを確認 | 主食の有無と非常時の代替は本番方針を別途定義 |
| 主食を基礎に副食を添える評価 | 料理の種類数に応じた心情。役割は区別しない | 菜ばかり3種を「整った食事」としない評価へ差し替える。効果量は未決定 |
| 病人・囚人への配膳 | 代理取餐Jobの実装あり（ソース確認） | 一膳化の代理経路は未検証。自力喫食の試作PASSを転用しない |

Daily Menuの自動生産計画はこれらと別機能。最終検証は自動生産OFFで行った。既存の調理Billで作り置きし、取餐だけを利用する方向を選べる。新たな料理人待機・食事時刻同期を実装し直す必要はない。

## 実喫食で確認した項目と前提

**調理工程を評価する試験ではない。** CoreのMealSimple/Fine/Lavishを完成済みの3料理として投入した。試作ではそれぞれ主食／汁／菜の役割を代用させたが、これらが日本料理であることや、本番の分類・性能を承認するものではない。

1. 各3食分を3台へ投入。実Pawnが3種の餐台を回って食べ、食物欲求が90%以上へ回復した。
2. 原実装では3個の小分け品を所持し、同じsessionの3食事記録が残った。一膳アイテムは存在しなかった。
3. 取餐による在庫減少`0.7999992`と摂取記録`0.8000001`が許容誤差0.002以内。栄養を複製していない。
4. 1台だけでも取餐Jobが成立。これは提示確認であり、欠品の全条件を網羅するものではない。
5. 0.12栄養の取り分けと、原料RawRice・既存の腐敗進行の引き継ぎを確認した。
6. 試作では同役割の重複料理を置いても各役割1品を選び、主食を先頭にした。
7. 既存BuffetJobの最後に一膳化を挿入。元の料理3個を一つの保持アイテムへ移し、外側のIngestは1回になった。
8. 膳の内部では元食品のIngestを各1回呼び、元食品に委譲した。Daily Menu記録が膳の分だけ二重に増えず、3品の栄養合計が維持された。

8は**効果量のバランス保証ではない**。MO食品のHediff重複、少量の高級品で一食全体が高評価になる問題、食中毒確率・特殊Compは別途設計・検証が必要。種類数ボーナスをそのまま採用する判断もしていない。

## 前提化のために必要な修正

### Daily Menu配布物の不具合

`DailyMenu.Supply.dll`の`DailyMenuSupply.ProcessingSupply`は、内部の調達準備ヘルパーを`Prepare(MenuMap)`と命名している。Harmonyはこれをパッチ準備用の予約メソッドとして実行し、Mapがない初期化時に例外となる。提供されている`Source/Supply.cs`の当該宣言と呼出を`PrepareIngredients`へ改名して補助DLLだけを再コンパイルすると、最終試験で解消した。

最終コピーとの差分は **`Assemblies/DailyMenu.Supply.dll`だけ**。本体DLLとその他の配布ファイルは変更していない。修正補助DLL SHA256は`33444460eb8f9861f2b90261228e94d8469d7c1c2380a587258a402db28d09ed`。修正DLL・第三者の全ソースを本リポジトリへ転載しない。正式配布時は修正版の入手・利用・配布条件を確認する必要がある。

加えて餐台と飲物台にMassを追加する独立XMLパッチが必要。検証値1は設定欠落の解消を確認するための仮値であり、建物重量の本番採用値ではない。

### AMJの一膳化

Daily Menuの選択結果を役割別に整え、取餐Jobの最後に一膳化を差し込む独立Harmonyパッチで自力喫食を確認した。既存の取餐・予約・栄養端数処理を再利用できる。すべてを独自料理OHとして作り直す必要性は、この範囲では認められない。

**ただし現物は実現性確認用で、製品パッチではない。** 実AMJ食品の分類・分量・評価、途中中断時の回収、膳の保存再読込・腐敗・運搬、病床・囚人、キャラバン、MOの食事効果、特殊食品対応が未受入。単純食事の通常経路廃止と非常食の扱いも今回実装していない。

今後の設計は **「修正済みDaily Menu＋AMJの役割・一膳化互換」** を基盤に進める。実Agricultureの依存メタデータ変更やユーザー環境への導入は、その製品化時に行う。
