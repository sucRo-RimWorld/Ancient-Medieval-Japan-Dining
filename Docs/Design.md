# AMJ — 新しい料理システム（Dining案）

**設計決定日: 2026-11-01 / 状態: 基本方針確定、詳細設計中、実装未着手**

## 0. 旧Diningの全面廃止と今回の位置づけ

本書は**旧Diningの改良案ではなく、新しいDining案の正本**である。作者決定により、過去のDiningの**完成済み料理の取り分け・配膳台・複数料理の一膳化・膳オブジェクト・旧品数評価・画像配置UIの構想はすべて廃止**する。旧設計の3:1:1栄養配分、2品/+2・3品/+4、旧3種ロール等は新設計に持ち込まない。新しく採用する場合には**別途承認**を必要とする。

旧コード/XML/配布DLL/About/旧テストは**現時点では旧方式のまま存在し、実装移行前の状態**である。以前の実機PASSは新案の動作を検証しない。移行時には旧ソース・旧DLL・Def・パッチ・依存関係・テスト・説明の整理を行い、旧セーブ参照への影響を別途判定する。**旧IDの維持を新設計の前提としない**。本設計反映だけでは何も撤去・配布・実装していない。

新案の**5種類の料理Bill、材料の分類・栄養・加工度、材料探索、料理製品**は、作者の指定では **Agricultureが実装担当**。本リポジトリは新Dining案の設計置き場とし、**Diningを実行Modとして存続させるか、Agricultureへ機能を集約するかは未決定**。新しいDining DLLや旧配膳ランタイムの維持を前提にしない。依存関係の再編は実装移行時にAgriculture/Projectと整合させる。

**設計更新:** 作者が**確定・採用した仕様は正本へ反映**し、未確定の検討案・提案・質問・例示数値は確定仕様として反映しない。確定が曖昧な場合は推測で決めず確認する。正本への反映は作業ブランチ・PR・実質レビューを経る。設計確定とコード/XML実装済みを混同しない。

## 1. 設計目的と確定方針

- 料理の種類を作り分ける競争軸は作らない（断念）。料理間の差は**材料の組み合わせ（段階を決める点数）・材料の加工度・名称・見た目・構成点数に応じた娯楽回復**で表す。
- 食事は**一品完結**とし、主食・汁・副菜・主菜・調味を別の完成料理でなく、単一レシピ内の**食材の枠**として扱う。
- バニラとMedieval Overhaul（MO）の通常食事BillはAgriculture側で廃止し、T1〜T5の5段階の料理Billへ置換する。保存食と携行食は別系統のBill。
- **U2の正式なBill段階名は確定**：T1「簡素な食事」、T2「普通の食事」、T3「手の込んだ食事」、T4「豪華な膳」、T5「贅沢な膳」。T1〜T3は「○○な食事」、T4〜T5は「○○な膳」で系統内の命名規則を統一する。**完成品名はT2〜T5で段階名固定、T1のみ条件付き個別名**とする。献立・評価は名称に詰め込まず情報欄へ分離する（4.1節）。
- 「N汁M菜」「本膳」は**名称にも内部の判定にも使わない**。段階の内部IDは**T1〜T5**。
- 段階に入った後の品数・点数を心情加点へ流用しない。加工度による上限付き心情差のみを段階内で扱う。

## 2. 材料栄養値と枠の基本規則

- 材料のThingの **Nutritionを直接修正**する。バニラの米・ベリー等が同値である問題を改善し、野菜は穀類より低くするがゼロにしない。波及する食料全体の数値調整はAgricultureの別作業。
- **U3の枠別消費方式は確定**：主食（T1の主材料を含む）・主菜は**実際のNutrition量を基準**に必要個数を求め、汁の具・副菜は**個数基準**で消費する混合方式。調味料・漬物は下記の確定済み個数規則に従う。**各枠に必要な具体的Nutrition量・個数はU3・U6で未決定**。野菜等のNutrition引下げを予定しているため、数値はAgricultureの原料栄養バランスと一体で評価する。XMLのみの都合で混合方式を諦めない。
- **調味料は対象枠ごとに1個、漬物は1個で副菜1枠**を満たす。Nutritionを調味料・漬物の1個分に合わせる方式は旧案であり、実装方法はU3に含める。
- 材料には複数のロールを指定できるが、**同じ1個を二つの枠に二重計上しない**。ロールは**材料**に付け、完成料理に付けない。
- 必要栄養量の端数処理など、RimWorld既存コードに依存する細部は**要確認**。

### 2.1 U3：完成品栄養と材料消費の確定方針（2026-11-03）

| 段階 | 完成料理1食のNutrition |
|---|---:|
| **T1 簡素な食事** | **0.9** |
| **T2 普通の食事** | **0.9** |
| **T3 手の込んだ食事** | **0.9** |
| **T4 豪華な膳** | **1.0** |
| **T5 贅沢な膳** | **1.0** |

- **構成点数によって完成品Nutritionを増減させない**。構成点数は既定の娯楽回復を担い、加工度は心情評価を担う（第6節）。T4/T5の栄養量も1.0より大きくしない。
- **栄養量基準**の主食・主菜については、各食材Thingの実際のNutritionに基づく消費個数で必要量を満たす。**個数基準**の汁の具・副菜、1枠1個の調味料、1枠1個の漬物は、低Nutrition食材の必要個数が過剰に膨らまないよう独立に扱う。漬物の「副菜＋調味相当3点」の採点例外は変えない。
- **投入栄養量は実際に消費した全材料（調味料・漬物を含む）のNutrition合計で評価する**。完成品と投入栄養量との比率・栄養効率について、現時点で一律の等価・補正係数を確定したとは扱わない。各枠の具体量、T2/T3最大点数探索時の食材消費、T4/T5固定献立の費用対効果、端数、作業量・技能・設備・腐敗期間・調味料/漬物生産量はU3/U6の残課題。

## 3. 材料枠と点数（確定）

| 料理上の枠 | 材料カテゴリ・条件 | 必要量 | 点 |
|---|---|---|---:|
| 主食 | T1は調理に使える未完成食材（卵を含む。乳製品・調味料・漬物・完成料理は除外）、T2〜T4は食用に加工済みの穀類、T5は精白米のみ | U3で確定 | 必須（0点） |
| 汁の味付け | **味噌・塩のみ** | 1個 | +1 |
| 汁の具 | 野菜・豆腐などの汁の具カテゴリ | 副菜枠より少量。必要栄養量／個数はU3・U6 | +1 |
| 副菜 | 副菜材料、または**独立した漬物カテゴリ** | 必要栄養量／個数はU3・U6。漬物は1個で1枠 | +2 |
| 主菜 | 栄養面で主菜に相当するタンパク源（肉・魚・豆腐など）。低エネルギーの野菜・海藻・山菜・キノコは除外 | 栄養量（具体値U3） | +4 |
| 副菜の調味 | 酢・醤油・味噌・塩などの調味材料 | 1個 | +1 |
| 主菜の調味 | 同上 | 1個 | +1 |

- **主菜4点、副菜2点**は作者指定。汁は**具+1**と**味付け+1**を独立加点。具も味付けもない汁は扱わない。醤油湯・塩湯は汁料理として扱わない。
- **漬物は副菜材料の一種ではない**。独立の漬物カテゴリから**1個で副菜1枠（+2）**を満たす。製造時に調味済みなので**副菜の調味を別途要求しない**。採点時は**副菜+調味相当の計3点**として扱う。野菜とその野菜の漬物は別ThingDefなので、副菜2枠へ別々に入れられる。
- 汁の味付けは**味噌・塩だけ**。醤油は副菜・主菜の調味にのみ使用。**出汁を廃止し、その+1点も存在しない**。名称「すまし汁」は使わない。
- 材料のThingDefが複数カテゴリに属してよい（例: 豆腐=汁の具・主菜）。ただし同じ実物を2枠に数えない。
- Billの材料フィルタでは、通常の食品分類に加え、**枠材料カテゴリを親カテゴリ配下に表示**し、枠単位で許可/禁止を設定できるようにする。

### 3.1 U1：食材分類の基本規則（2026-11-01 確定）

**料理ロールは材料ThingDefに付ける。** 主菜は単に「高いNutrition」ではなく、ゲーム上のタンパク源として扱う食品群を指定する。素材の現実のエネルギー量を無視して野菜・山菜・キノコ・海藻を主菜に昇格させない。個別食品をAMJに採用するかは、Agricultureの歴史的選定基準で先に決める。ロールの一般則を定めたことは、未実装食品の採用や製造レシピ追加の決定を意味しない。

| 食品群 | T1 | T2〜T5での料理ロール・扱い |
|---|---|---|
| 雑穀・麦・蕎麦・米の**脱殻後の食用穀粒**、料理用の穀粉 | 使用可 | **主食**。収穫束・籾・未脱殻粒などは料理材料にしない。T5は精白米のみ（玄米・米粉も不可） |
| 野菜類 | 使用可 | **汁の具・副菜**。主菜にはしない |
| 肉・魚 | 使用可 | **主菜**。干魚・小魚などは品目・加工状態・用途に応じて分類し、全品一律の複数ロール採用はしない |
| 豆腐 | 使用可 | **汁の具・副菜・主菜**を兼任可能。ただし同一ThingDefを複数の食材枠で兼用しない |
| 豆類 | 食用として適切に処理された場合に使用可 | **副菜**を基本候補。汁の具・主菜への一律割当ては行わず、食品・用途別に判断する |
| キノコ・山菜・海藻 | 使用可能な食材は可 | **汁の具・副菜**の候補。**主菜不可**。アク抜き等の必要な処理を省略しない |
| 木の実・果実 | 使用可能な食材は可 | 品目・調理用途によって個別判定。穀類の主食カテゴリには自動登録しない |
| **卵** | **使用可（T1限定）** | **T2〜T5は使用不可** |
| **漬物** | **使用不可** | **独立した漬物カテゴリ**。1個で副菜+副菜調味相当の計**3点**を満たし、別の副菜調味料は不要 |
| **調味料** | **使用不可** | 汁用は塩・味噌のみ。副菜・主菜用は塩・味噌・醤油・酢など、用途ごとに分類 |
| **乳・乳製品** | **使用不可** | **T1〜T5すべてで使用不可**。チーズ・チーズ料理はAMJの通常供給・製造対象から除外する方針 |
| **加熱乳** | 料理材料としては使用不可 | **独立した飲用食品**として採用。生乳を加熱して食中毒リスクを抑え、搾乳可能な家畜のゲーム上の価値を維持する。T1〜T5の料理・ロール採点には含めない |
| 完成済み料理 | 使用不可 | 食材として再投入しない（独立食品の漬物は上記の特例） |

**乳の例外に関する根拠と範囲:** 古代には牛乳を加熱して服用する記述があるが、中世日本の庶民に乳飲用・チーズ食が一般的だったとの根拠は確認できない。加熱乳の採用理由は**ゲームバランスが主目的**。畜産者が搾乳した乳を飲んでみる可能性を認め、搾乳できる動物のメリットがゼロにならないようにする。**生乳の直接飲用は不可**とし、加熱乳は食中毒防止のための加工を必要とする。MOのチーズ等を残すかどうかは品質・既存加工設備の利点からではなく歴史適合性で判断し、AMJでは不採用とする。既存Defやセーブ参照の物理的削除方法はU12・U13の実装互換検討に委ねる。

**他Mod食材の自動分類（B案、確定）:** AMJ食材は明示分類、バニラ・MOはAgricultureで歴史的選定・除外した内容を優先する。その他Modの食材は、ロード後に取得できる種類・食品情報から**判別できるロールのみ自動付与**する。判別不能でも食用の未完成材料と分かるならT1にのみ使用可能とし、乳製品・完成料理等の除外は優先する。歴史的適合性の判定対象をすべての他Modに広げない。**他Mod向けの手動ロール設定UI・個別対応表は設けない**（通常のBill材料フィルタによる許可/禁止は維持）。AMJ・MOが明示的に禁止した食材、未脱殻穀類などを自動分類で料理に復帰させない。加工度が未指定なら0の既定方針も維持する。

**U1の完了範囲:** 上記は料理ロールの基本分類と他Modの既定動作の確定。個別品目の歴史的採否・DefNameの網羅表、魚介乾物や豆類の個別ロール、必要数量・栄養量、実際の加熱乳のRecipe/負担/食中毒確率、チーズ供給経路の停止方法は別途Agricultureの品目選定・U3/U6/U9/U12/U13等で扱い、**確定済みと偽らない**。

## 4. 5段階Bill（確定）

| 段階 | Billの条件 | 点数 |
|---|---|---:|
| **T1** | 調理可能な未完成食材（卵を含み、単独でも使用可。乳・乳製品・漬物・調味料・完成料理は除外）。バニラの簡単な食事相当 | 0 |
| **T2** | 主食（穀類）＋帯内に収まる材料枠を自動構成 | **1〜4** |
| **T3** | 主食（穀類）＋帯内に収まる材料枠を自動構成 | **5〜8** |
| **T4** | 固定: 主食（穀類）＋汁の具＋主菜＋主菜調味＋副菜＋副菜調味（漬物なら省略）。汁の味付けは任意+1 | **9〜10** |
| **T5** | 固定: 主食（精白米）＋汁の具＋汁の味付け＋主菜＋主菜調味＋副菜**2枠**（各調味、漬物なら省略） | **13** |

**漬物を使うとき:** 調味枠の実材料を要求しなくても、漬物1個を**副菜+調味相当（3点）**とみなすため、T4=9〜10、T5=13を維持する。この仕様を単に「漬物は副菜材料」と置き換えてはいけない。

- 完成品の段階は**Bill（XML）**で決定する。T2・T3のC#材料探索は、その段階の**点数帯内で最大点数**となる組合せを選ぶ。
- 同点なら**腐敗が近い材料優先**（腐敗しない材料は最後）。同一枠でのスタック選択も腐敗期限、次いで距離で決める。
- T2上限は**4点（作者指定）**、T3上限は**T4の最低点数−1**。点数と帯をソースに固定せず**modExtensionデータ**で管理する。
- **T2・T3は点数帯が枠数の上限を兼ねる。総枠数の別上限は設けず、帯内で同一ロールを複数枠選んでもよい**（ThingDefの枠間重複禁止は維持）。調味枠は対応する汁の具・副菜・主菜がある場合にのみ使用・加点し、調味料だけで点数を作らない。
- T4・T5は品数を**固定強制**する。膳系は副菜・主菜の各調味を必須とする（漬物の副菜調味は例外）。
- 主菜4点だけでもT2帯に収まるので、T2・T3が肉・魚を自動消費し得る。**方針未決定 U18**。主菜を初期フィルタから除外する案は検討対象であり、採用済みではない。
- 帯と固定構成は同時に満たす必要がある。材料1枠を勝手に分割/二重計上して点数を作らない。

| 段階 | 固定Bill名 | 系統 |
|---|---|---|
| **T1** | **簡素な食事** | 食事 |
| **T2** | **普通の食事** | 食事 |
| **T3** | **手の込んだ食事** | 食事 |
| **T4** | **豪華な膳** | 膳 |
| **T5** | **贅沢な膳** | 膳 |

- **Bill名は段階ごとに固定**し、完成料理名とは分離する。内部IDのT1〜T5および第4節の点数・材料要件は変更しない。
- **完成料理名はT2〜T5では段階名で固定**し、材料を列挙しない。**T1のみ**単品で、実際の材料と調理内容から個別料理名を適切に特定できる場合に限り個別名を使用する。それ以外は「簡素な食事」。材料のみから実行していない調理法（炊く・焼く・煮る等）を断定しない。T1の個別料理名判定条件・名称対応表は未確定。

- 「豪華」「贅沢」等は段階差を直感的に示す**表示名**であり、材料構成の点数を心情評価に二重加算しない。構成点数は別途娯楽回復の評価に使用する（第6節）。バニラの三段階をそのまま日本料理名へ読み替える仕様ではない。
- **献立は完成品名に連結しない**。選択時情報欄に献立概要、詳細情報（InfoCard）に主食・汁・主菜・副菜・調味料などの材料割当てと、構成点数・加工度・心情効果・娯楽回復の評価数値および計算根拠を表示する。存在しない食材枠を表示上で補完しない。具体的なUI配置と表示文言はU17、数値はU4/U10等で未確定。

## 5. 同じThingDefの枠間重複

- 汁の具・副菜・主菜などで、**異なる枠に同じThingDefを重複利用しない**。同一枠内の複数個と複数種類の混在は認める。C#探索で強制。
- **汁の味付け・副菜の調味・主菜の調味の3枠は例外**。同じ塩や味噌を別枠へ各1個ずつ消費してもよい。
- 上記の厳密な適用範囲についての細部は**U5**。ただしこの例外を削除したり、同じ実物の二重使用を許したりしない。

## 6. 心情と加工度

- **心情効果**は料理段階の基本効果と、同じ段階内における**材料の加工度**による追加効果で決まる。材料の構成点数（枠/品数）は心情に二重加算しない。
- **構成点数（T1=0、T2=1〜4、T3=5〜8、T4=9〜10、T5=13）は、食事時の娯楽欲求回復に反映する**。より高い構成点数を得る追加材料のゲーム上の利益とする。T1の構成点0はこの追加娯楽回復なし。実際に決まった構成点数を表示・計算に使用し、同段階でも点数差を反映する。
- 娯楽回復の**具体的な換算率・上限・他の娯楽処理との整合は未決定**。娯楽ゲージ上限を超えた過剰回復は起こさず、通常の娯楽活動を全面的に代替する前提にはしない。心情に構成点数ボーナスを追加したり、栄養量増加を今回の確定効果として加えたりしない。
- 各ThingDefに静的な**加工度modExtension**を付与し、材料ごとの値を合算し上限を設ける。加工履歴追跡は不要。
- 生の食材・加工度が付与されていない他Mod材料は**0**。
- **加工度による段階内の最大心情差は、段階間の心情差より小さくする**。具体値U4・U10。

## 7. 製品・保存・画像

- 完成品は**一品完結**。**スタック統合条件は確定**：料理段階、完成品の表示名（T1の条件付き個別名を含む）、実際の献立（使用材料ThingDefと主食・汁・主菜・副菜・調味などの枠への割当て）、構成点数、加工度評価、特殊食材由来の効果（人肉・虫肉等）が一致する食事だけを統合できる。同じ表示名・同じ段階でも、献立または評価が異なれば別スタックにする。情報欄に表示する献立・評価を統合時に失わないこと。
- **投入材料の個数・製造者・製造日時のみの違い**は、献立・最終評価・ゲーム上の効果が一致する限り、独自のスタック分離理由にしない。腐敗・食中毒など既存ゲームの状態や統合制約は維持し、異なる状態の混在・消失を起こさない（具体的な既存APIとの接続は実装時に確認）。
- 実プレイでは生産・備蓄食材が偏り、献立が極端に変化し続けるとは限らないため、**スタック細分化対策のために献立情報を捨てたり、異なる献立を強引に統合したりしない**。保管上の実害が確認された場合のみ対処を再検討する。
- 初期画像は**段階ごとの固定画像**。後から**枠ごとの重ね描き（C#）**を追加する。
- 完成時に確定する各食材の献立内ロール割当てと評価結果を、選択時・詳細情報で確認できるようにする。表示のために調理方法を推測せず、数値の計算ロジックと表示を一致させる。
- 保存食・携行食はT1〜T3の食事系・T4〜T5の膳系とは**別Bill**。品目と仕様はU8。
- 完成品の**栄養量と材料枠の消費方式**は第2節・2.1節で確定。具体的な必要個数・投入栄養総量との効率、作業量、技能、設備、腐敗期間、調味料・漬物の産出数、総負担はU3/U6の残課題。
- T1〜T5をバニラの「簡単・手の込んだ・豪華」の**3つの日本料理への置換**として解釈しない。料理の材料構成とバニラのグレードは別の分類次元。

## 9. 時代考証 — 確認状況を分離

- **本膳料理:** 室町武家の饗応と関係。汁・菜の数で表す型の名称が中世に成立していたかは**未確認**。本システムの命名/判定には不採用。
- **庶民の日常食:** 中世庶民の日常献立の直接資料は**未確認**。江戸中期の「飯・味噌汁・漬物」を中世に直接外挿しない。より簡素だった可能性は**推測**。
- **白米:** 上流層・晴れの日との関係は**裏付け調査待ち**。精白米をT5条件とするのは現在のゲーム設計決定。
- **乳・乳製品:** 古代の宮廷・医書に乳・蘇・加熱服用の史料はあるが、中世庶民にチーズや乳飲用が一般的だったとは確認できない。MOチーズは不採用。例外の加熱乳は畜産のゲームバランスを主目的として採用し、歴史的な普及を主張しない。
- **出汁:** 現代に相当する出汁の記述（室町後期料理書の鰹節）や江戸期の高価格から、庶民の日常的利用は確認できず**採用しない**。史料精査はU16。
- **醤油:** 文字の記録が室町、商業化が室町末期、現代型製法は江戸後期という整理。具体の原料/流通/利用年代はU16で裏付けを検討。
- **さつまいも・じゃがいも:** 近世以降のため採用しない。
- 調査する際は**確認済み史実と推測**を分離し、弱い出典（記念日サイト・商業ブログ等）は信頼度を明記する。出典の文章はそのまま転載しない。
